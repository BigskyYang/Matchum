## 0. 배경과 목적
- 서비스 흐름: 웹 설문 → 재준 님 개인 모델(v1.4, `bigskyyang/web/src/data/nutritionModels.json`)이 영양소 14개마다 부족 위험 "높은 편/보통/낮은 편" → 웹이 '살펴볼 영양소'를 고름 → 준혁 님 제품 목록에서 성별·나이에 맞는 건강기능식품 정보를 보여 줌.
- 문제: 준혁 님 지금 방식(영양소 × 대상 칸마다 3개)은 사람마다 영양소별로 따로 나열해서 (1) 한 사람이 평균 4~5개 제품을 보고 (2) 같이 먹으면 상한을 넘는 경우가 생기고 (3) 비타민 B군 칸에 B1·B2가 없는 제품이 1순위로 나옴.
- 원칙(사용자 결정): **필요한 사람에게 필요한 만큼만**, 그리고 **처방처럼 보이지 않게** (조합을 정해 주지 않고 정보로만, 사용자가 고름).
- 결론: 준혁 님 변경안(11/4 16:18 슬랙 `영양제_분류_필터링_변경안시험용.pdf`)의 8·9단계(품질 거르기, 촘촘한 점수, 70점 탈락)는 **그대로 쓰고**, 마지막 화면 단계에 아래 규칙을 얹음.

## 2. 규칙 (코드: `시안_합친방식_v2.py`)
### 2-1. "덮는다" (cover)
- 제품 i가 영양소 n을 덮음 = 하루 함량 ÷ 1일 영양성분 기준치(`DV`) ≥ **30%** (준혁 님 점수에서 감점이 없는 선)
- 비타민 B군: `b_percent()`의 **B1 또는 B2**가 ≥ 30% (재준 님 모델의 B 신호가 티아민·리보플라빈이라서)
- 식이섬유: 9단계 결과에서 영양소가 '식이섬유'인 제품
- 대상 영양소 8종: 비타민 B군, 비타민 C, 칼슘, 마그네슘, 아연, 철, 엽산, 식이섬유 (비타민 D는 재준 님 모델에 없어서 개인 결과에서 안 나옴)

### 2-2. 안전 거르기 (화면에 넣기 전)
- 제품명에 어린이 의심 단어가 있으면 **확인 전까지 화면에서 뺌**
  `키즈|어린이|아이들|아이용|우리아이|주니어|청소년|성장|키튼|쑥쑥|키크|키 크|베이비|유아|kids|junior|baby`
  → 9단계 후보에서 14개 걸림: 성장공식 칼비아, 쑥쑥하이업 칼마디 젤리, 뼈가튼튼 밀키튼+ PLUS, 리틀팡 성장튼튼, 마이니 하이쑥쑥 칼슘&비타민D, 닥터. 비타민젤리스틱 튼튼쑥쑥, 수퍼 키튼 젤리, 쁘띠앤베베 징크칼마디 쑥쑥 젤리, 성장에 좋은 키온 KEYON, 튼튼성장 칼슘 젤리, 키노피오 쑥쑥튼튼 칼슘젤리, 프리미엄 성장 꾸미, 데일리 쑥쑥 칼슘 멀티비타민 젤리, KoreanVita SsukSsuk Vita
  (주의: '아이' 하나만 쓰면 아이오딘·아이언이 잘못 걸림)

### 2-3. 누구에게 (① 대상자)
- 재준 님 모델 "높은 편"(`p ≥ cuts[k].mid_high`) **그리고** 부족 확률 `p ≥ 0.5` ("10명 중 5명 이상", 유형 결과와 같은 기준)인 영양소만
- 모델 키 → 제품 영양소: vitamin_b1·vitamin_b2 → 비타민 B군, vitamin_c, calcium, magnesium, zinc, iron, folate, fiber
- 걸린 영양소가 없으면 제품 칸을 보여 주지 않음 (음식 안내만)

### 2-4. 영양소별 목록 (준혁 님 10단계 재현 + B군 규칙)
- 영양소 n, 내 대상(일반 + 성별 + 50세 이상이면 시니어) 줄만
- B군은 2-1의 B1·B2 덮는 제품만
- 수면 6시간 미만 또는 스트레스 높음(`ML_stress == 1`) → 주의 원료(카페인·간) 제품 제외
- 정렬: [끼니 불규칙이면 하루 1개 먼저] → 상 → 점수 ↓ → 하루 개수 ↑ → |log(기준치%/100)| ↑ (100%에 가까운 순) → 원재료 수 ↑
- 같은 업체는 한 번만, **최대 3개**
- 끼니 불규칙 = 아침·점심·저녁 중 하나라도 주 1~2회 이하 (`ML_*_freq_ord ≤ 1`)

### 2-5. "한 제품에 여러 영양소가 함께 든 제품도 있어요" (② 여러 영양소 칸)
- 내 영양소가 2개 이상일 때만. 후보 = 내 대상 제품 중 내 영양소를 **2개 이상** 덮는 제품 (2-4와 같은 생활습관 거르기)
- 정렬: 덮는 내 영양소 수 ↓ → **내가 안 걸린 영양소까지 덮는 수 ↑ (종합비타민 쏠림 방지)** → [끼니 불규칙이면 하루 1개] → 상 → 점수 ↓ → 하루 개수 ↑ → 기준치 100%에 가까운 순 → 원재료 수 ↑
- 같은 업체 한 번만, 최대 3개
- 이 칸 1순위가 덮는 영양소의 목록에는 "위 제품에 함께 들어 있어요" 표시

### 2-6. 주의 문구 (③)
- 영양소별 목록 1순위들 + 여러 영양소 칸 1순위를 **모두 먹는다고 가정**하고 상한 성분 10종(`UL`)을 더해 하나라도 넘으면 → "함께 드시면 ○○이 상한을 넘을 수 있어요"
- 조합을 정해 주지 않고 안내만 함

### 2-7. 화면 순서 (처방처럼 보이지 않게)
```
먼저 음식으로: 영양소마다 food_guidance.py 음식 예시
음식으로 챙기기 어렵다면 ▸ 한 제품에 여러 영양소가 함께 든 제품도 있어요 (2-5)
▸ 영양소별 제품 정보 (접힘, 2-4)
⚠ 주의 문구 (2-6, 해당될 때만) / 이미 드시는 영양제와 겹치는지 확인 / 전문가 상담 안내
```
쓰지 않는 표현: "드세요", "이 조합이면 충분해요", "필요해요", 하루 몇 개 같은 용량 안내.

### 2-8. 자동 점검 (사람 확인을 줄이기)
화면에 나올 수 있는 제품(5,320명 시뮬레이션에서 한 번이라도 나온 제품)만 점검:
- 대상: 제품명 어린이 단어 / 기능성에 '어린이|성장기|청소년'
- 영양소: 덮는 영양소마다 기능성 원문에 이름 **또는 식약처 고시 기능 문구**가 있는지 (예: 칼슘 '뼈와 치아 형성|골다공증 발생 위험', 비타민 C '결합조직 형성|철의 흡수', 마그네슘 '에너지 이용|신경과 근육 기능 유지', 아연 '정상적인 면역기능|세포분열', 철 '체내 산소운반|혈액생성', 엽산 '세포와 혈액생성|태아 신경관|호모시스테인', B1·B2 '탄수화물과 에너지 대사|체내 에너지 생성', 식이섬유 '차전자피|배변')
- 목적: 기능성에 `체지방|혈당|혈압|관절|연골|피부(?!와 점막)|모발|기억|인지|눈 건강|눈의 피로|간 건강|전립선|갱년기|수면|긴장`
  (비타민 A의 '피부와 점막', 차전자피의 '콜레스테롤'은 영양소 자체 기능이라 제외)
- 결과: 133개 중 **4개**만 걸림 → 사람이 확인

## 4. 준혁 님 코드에 반영을 제안하는 것 (우선순위 순)
1. **1단계 어린이 키워드 보강**: 위 2-2 단어 추가 (지금 14개가 '일반'으로 남아 있음)
2. **9단계 B군 규칙**: 재준 님 모델과 연결되는 B군 줄은 B1 또는 B2가 기준치 30% 이상인 제품만 (지금 B군 1~3순위가 B12·판토텐산·나이아신 단일)
3. **3단계 종합비타민 예외 확인**: 이름에 멀티·종합이 있으면 목적 충돌 검사를 건너뛰어서 홍삼·은행잎 든 종합비타민이 남음 (자동 점검에 걸린 4개: 간편한, 독도이뮨 홍삼 멀티비타민 미네랄, 프리미엄 올인원 멀티팩, 뉴메이트 오메가3 마그네슘 비타민B)
4. **10단계 출력 형식**: 지금처럼 칸마다 최대 3개 목록(`web_products.csv`)은 그대로 두고, 웹이 2-5·2-6을 계산할 수 있게 **제품 표**(품목제조신고번호, 대상, 덮는 영양소 8종 True/False, 상한 성분 10종 하루 함량, 하루 개수, 주의 원료, 등급, 점수)를 같이 내보내기. 웹 연결은 팀장님(대천 님)과 정함

## 5. 아직 정하지 않은 것
- 대상자 기준 A안(p ≥ 0.5) 확정 여부 — 보는 사람이 거의 안 줄어서(69%) 화면 구성(음식 먼저)으로 다루는 중
- 생활습관 규칙 2개(카페인 제외, 하루 1개 먼저)는 데이터로 검증하지 않은 **설계 가정**
- 숫자 기준(30%, 0.5, 그리고 준혁 님 500%·원재료 30개·70점)은 모두 시험용
- 비타민 D 제품 위치 (개인 모델에 D 없음 → 유형 결과 쪽에서 안내할지)
