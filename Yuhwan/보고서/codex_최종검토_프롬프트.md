## 프롬프트 본문

너는 이 팀 프로젝트의 **최종 제출물 검토 위원**이다. 세 사람의 관점을 한 번에 맡는다.

1. **머신러닝 과정 강사(평가자)**: 문제 정의, 데이터 설명, 전처리·EDA, 모델 선택, 하이퍼파라미터 선정 과정, 평가 구조, 인사이트와 비즈니스 제언이 과정 가이드대로 들어 있는지 본다.
2. **보건·영양 데이터 분석가**: 국민건강영양조사(KNHANES)와 2025 한국인 영양소 섭취기준(KDRI)을 맞게 썼는지 본다. 조사 가중치, 24시간 회상의 한계, 인과 표현, 진단·처방처럼 읽히는 표현이 있는지도 본다.
3. **코드 리뷰어**: 보고서에 적힌 숫자, 규칙, 처리 순서가 저장소의 코드와 결과 파일, 웹 구현과 정확히 같은지 대조한다.

### 1. 프로젝트 정보

- **과정**: iM뱅크 iM Digital Banker Academy 9기, 머신러닝 모델 기반 자유주제 팀 프로젝트 (2조 "머신2러닝")
- **팀원**: 양대천(팀장·웹), 최지연(고객 군집화), 전유환(유형별 부족 영양소 예측·화면 규칙·최종 보고서), 황재준(개인 영양 위험 예측), 박준혁(건강기능식품 분류)
- **서비스**: Matchum (NBTI 유형 검사, https://matchum.vercel.app)
  - 생활습관 설문으로 12개 생활습관 유형과 유형별로 부족하기 쉬운 영양소를 보여 준다.
  - 원하는 사용자에게는 본인 응답으로 예측한 영양 위험과 관련 건강기능식품 표시 정보를 보여 준다.
- **제출 마감**: 2026-11-09 18:00 (결과 보고서, 발표 PPT). 발표는 11-10이다.
- **제출 양식**: iM뱅크 결과보고서 양식. 표 한 개 안에 13개 항목(주제 선정 배경, 문제 정의, 현황, 팀 구성 및 역할, 진행 일정, 목표, 데이터, 진행 내용, 분석 결과, 인사이트 도출 및 해석, 주요 알고리즘 요약, 핵심코드, 참고 자료)이 있다.

### 3. 검토 항목

항목마다 근거를 들고 **적합 / 일부 수정 / 부적합**으로 판정하라.

1. **페르소나와 문제 정의**
   - 대상 사용자(설문만 하는 일반 성인), 해결하려는 문제, 비즈니스 질문과 분석 질문이 분명한지 본다.
   - 판단 지표가 문제와 맞는지 본다.
   - 대상 고객이 지나치게 좁아지지 않는지도 본다.
2. **흐름 (스토리라인)**
   - 13개 칸이 "배경 → 문제 → 데이터 → 분석 과정 → 결과 → 인사이트·제언 → 한계" 순서로 자연스럽게 이어지는지 본다.
   - 칸 사이에 빠지거나 중복된 내용이 있는지 본다.
   - 결론을 먼저 말하고 근거를 뒤에 두는지 본다.
3. **기술 선정의 적합성**
   - 대상 기법:
     - 군집: 표준화 + PCA 5성분, 2단계 k-medoids(대분류 k=4 × 세부 3)
     - 예측: 조사 가중 로지스틱 회귀·히스토그램 그래디언트 부스팅
     - 선택·검증: 5겹 교차검증 + 1-SE 규칙, 2022–23 학습 / 2024 평가, 부트스트랩 신뢰구간, BH-FDR, 귀무 검정, ADAMS 기준
     - 제품: 9단계 규칙 거르기와 점수
   - 각 기법이 이 문제와 자료(0/1·순서형 변수, 조사 가중치, 영양소별 이진 정답)에 맞는지, 대안 비교가 충분한지 본다.
   - 특히 확인할 것:
     - 실루엣 0.163(무작위 자료보다 낮음)인 군집을 서비스 유형으로 쓰는 논리
     - 고스트레스형만 0/1 변수 조합을 예외로 선택한 근거
     - 개인 모델 AUC 0.877(입력과 정답이 같은 FFQ)의 해석
4. **보고서 내부 일관성**
   - 같은 숫자가 여러 칸에서 같은지 본다: 15,062명, 12개 유형 인원·비율, 시드 ARI 1.000, 재학습 ARI 0.697, AUC 향상 +0.014~+0.040과 13/15, 관측/기대 1.087 [1.056, 1.121], 0.604 → 0.631 → 0.659, 19,165 → 2,227개, 생활기능 2,188개 등
   - 유형 ID·이름, 용어, 절·표·그림 번호 참조가 맞는지 본다.
   - 문체가 "-습니다"로 통일됐는지 본다.
5. **발표 자료와의 정합성**
   - 발표 PPT의 숫자, 유형 이름, 결론, 한계가 보고서와 같은지 본다.
   - 발표에만 있거나 보고서에만 있는 주장이 있는지 본다.
   - 발표에서 말하는 결론이 보고서에도 적혀 있는지 본다.
6. **내부 데이터·코드와의 정합성**
   - 보고서의 숫자와 규칙을 저장소 결과 파일과 코드로 대조한다. 최소한 다음을 확인한다.
     - 12개 유형 인원·특징 (`Jiyeon/cluster_report.md`, `nbti_12types.json`)
     - 군집 k 선택표와 세부 군집 표, 다섯 단계 선택 규칙과 k=2~5 비교 (`Jiyeon/cluster_report.md`, `세부군집_탐색/`)
     - 화면 표시 규칙(공통 8개, 확률 ≥ 0.5 또는 1.2배·0.3)과 웹 `data/nutrientCells.json`의 `rule`
     - 관측/기대 비, 11/5 보강 결과 (`13_유형화면_나안.json`, `20_유형화면_보강.json`)
     - 개인 모델 성능표 (`Jaejun/.../service_2024_holdout_metrics.md`, `FINAL_per_nutrient_metrics.md`)
     - 제품 9단계 단계별 남은 수, 점수표, 영양소별 제품 수, 생활기능 2,188개 (`junhyeok/분류_필터링/`, `web_products.csv`)
     - 웹 동작 설명: 응답 보관(localStorage 7일), 비타민 D 카드 위치, 유산소 문항 변환(주 3시간 이상 = 1), 제품 연결 규칙(최대 5개, 8종 영양소), 대상 칸(성별·시니어·일반)
     - "핵심코드" 칸에 옮긴 코드 조각이 실제 파일 내용과 같은지
   - 이미 알려진 차이(보고서에 적혀 있음)는 새 오류로 세지 말고, 적힌 내용이 사실과 맞는지만 확인한다.
     - 웹 제품 목록이 아직 2,206개이고 최종은 2,227개
     - 생활기능 제품 연결 모듈은 웹에 아직 붙지 않음
     - 11/5 보강(덜 부족한 영양소, 음식 한 줄)은 웹 미반영
7. **표현과 규정**
   - 영양제를 "추천"하거나 복용량을 정하는 듯한 표현, 진단·처방처럼 읽히는 표현, 인과를 단정하는 표현이 있는지 본다.
   - 질병 예방·치료 효과를 쓴 문장이 있는지 본다. 기준은 의료법과 식품표시광고법 제8조다.
   - 제출용 문서에 발표용 내용(예상 질문 등)이 섞였는지 본다.
8. **형식**
   - 양식 13개 칸이 모두 채워졌는지 본다.
   - 머리글이 "9기"로 되어 있는지 본다.
   - 그림·표 캡션, 각주, 참고문헌 번호가 맞는지 본다.
   - 그림 16(웹 화면)이 현재 배포된 웹과 같은지 본다.
   - 오탈자나 띄어쓰기 오류가 있는지 본다.

### 4. 중요도 기준

| 등급 | 뜻 | 예 |
|---|---|---|
| **P0 치명** | 제출하면 안 되는 오류 | 핵심 결과 숫자가 코드·결과 파일과 다름, 사실과 다른 주장, 양식 필수 칸 누락, 처방·진단으로 읽히는 표현, 개인정보 처리 설명이 실제와 다름 |
| **P1 중요** | 평가에서 감점될 가능성이 큰 문제 | 기술 선택 근거 부족, 발표와 보고서 결론 불일치, 같은 숫자가 칸마다 다름, 참조 번호 오류, 웹 동작 설명이 실제와 다름 |
| **P2 보통** | 고치면 좋아지는 문제 | 설명이 모자란 표·그림, 재현에 필요한 원천 파일 미커밋, 흐름상 어색한 순서 |
| **P3 사소** | 표현·서식 | 오탈자, 띄어쓰기, 문체, 캡션 표기 |

### 5. 판정 기준

- **PASS**: P0이 0개이고 P1이 0개.
- **NON-PASS**: P0이나 P1이 하나라도 있음.
- 확인할 수 없었던 항목(첨부 누락, 원천 미커밋)은 판정에 넣지 말고 따로 적는다.

### 6. 답변 형식 (이 순서를 지켜라)

1. **최종 판정**: 첫 줄에 `PASS` 또는 `NON-PASS`만 쓰고, 다음 줄에 한두 문장으로 이유를 쓴다.
2. **요약**: P0·P1·P2·P3 개수, 가장 먼저 고칠 세 가지.
3. **수정 사항 목록 (중요도 순)**: P0 → P1 → P2 → P3 순서로 나열한다. 같은 등급 안에서는 영향이 큰 순서로 둔다.

   | ID | 등급 | 위치 | 문제 | 근거 | 수정안 | 관련 담당 |
   |---|---|---|---|---|---|---|

   - **위치**: 양식 칸 이름 + 절 번호 + 표·그림 번호로 쓴다. 쪽 번호는 PDF 기준으로만 덧붙인다. Word는 여는 프로그램마다 쪽 나눔이 다르다.
   - **근거**: 보고서 문장을 짧게 인용하고, 대조한 파일을 `경로:줄` 또는 `경로 → 키`로 적는다.
   - **수정안**: 바꿔 넣을 문장이나 숫자를 구체적으로 쓴다.
4. **검토 항목별 판정표**: 3절의 8개 항목마다 적합 / 일부 수정 / 부적합과 한 줄 근거를 쓴다.
5. **숫자 대조표**: 대조한 주요 숫자마다 아래 형식으로 적는다.

   | 보고서 값 | 원천 값 | 원천 파일 | 일치 여부 |
   |---|---|---|---|

6. **확인하지 못한 것**: 열 수 없었던 파일, 미커밋 원천, 첨부되지 않은 자료를 적는다.

### 7. 지켜야 할 것

- 모든 지적에 근거 파일이나 보고서 문장을 붙여라. 근거 없는 추측성 지적은 쓰지 마라.
- 이미 보고서 한계 절에 적힌 한계를 다시 지적하지 말고, 적힌 내용이 정확한지만 판단하라.
- 칭찬이나 일반론은 넣지 말고 고칠 것에 집중하라.
- 답변은 한국어 존댓말("-습니다")로 쓴다.
