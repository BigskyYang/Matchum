## 2. 팀장님 — 웹 유형별 영양소 결과표 (11개 유형 사용 결정 반영)

자세한 내용: [04_웹결과표_입력CSV.md](04_웹결과표_입력CSV.md)

1. `build_nutrient_profiles.py` / `export_model.py`가 아직 **KMeans 형식**(`Main_Cluster`, KMeans 3단계 `model.json`) 기준 → 11개 유형 파일(`Macro_Cluster`, k-medoids)에 맞춰 수정이 필요해 보여요
2. **Low/Mid/High 구간 문제**: 사람별 예측확률 기준 구간(`risk_thresholds.json`)을 유형 평균 비율에 쓰면 → **인은 18개 유형 전부 High, 칼슘·비타민A·엽산·칼륨 등은 High 0개**
   - 제안: 유형 결과표는 상대 기준(유형 특이 = 성별·연령 보정 오즈비 ≥ 1.2 / 공통 주의 = 미달률 ≥ 50%, 또는 유형 비율 ÷ 전체 비율)으로
3. 입력 CSV는 `Yuhwan/영양분석/05_웹결과표용_내보내기.py`로 만들 수 있어요 (사람 단위 데이터라 깃허브엔 안 올림, 필요하면 드라이브로 공유)

## 3. 재준님 — 예측 모델 입력 변수 누수 가능성

자세한 내용: [03_예측모델_누수확인_요청.md](03_예측모델_누수확인_요청.md)

- `HEI_PROTF`·`HEI_DAIRY`가 정답(영양소 부족)과 **같은 24시간 회상**(이용지침서 p250)에서 계산됨
- 재현: 같은 날 식품군을 입력에 넣으면 AUC +0.12~0.23 (인 0.713 → 0.895, 단백질 0.643 → 0.866), 비타민C만 +0.015 → Prototype v1 AUC와 거의 같은 값
- **질문**: ① 두 변수를 뺀 모델 AUC가 있는지 ② 웹 Q25·Q26 → HEI 변환 검증 계획 ③ 발표 때 두 버전 같이 보고할지
- 참고: 두 기준이 같은지 확인 — 제품분석에서 만든 부족 여부 비율이 노션 기록과 소수점까지 일치 (같은 2025 KDRI 기준)
