# [제품분석 → 준혁님] 개인별 영양제 추천 함수 전달 (2026-11-03)

> 11/3 회의로 영양제 추천은 **개인화 트랙**(재준님 개인 예측 → 준혁님 필터링·추천)에서 하기로 했어요.
> 제가 유형 기반으로 만든 추천 로직을 **입력만 개인으로 바꿔 함수 하나로** 묶었어요. 준혁님은 재준님 예측 결과만 연결하시면 돼요.
> 코드: [`제품분석/recommend_api.py`](../제품분석/recommend_api.py) · 검증: [`제품분석/06_개인추천_함수_검증.py`](../제품분석/06_개인추천_함수_검증.py)

## 1. 쓰는 법 (3줄)
```python
from recommend_api import Recommender, needs_from_model
rec = Recommender()                                                     # 제품 데이터 1번만 읽음
needs, basis = needs_from_model(lifestyle_결과, habitual_결과)           # 재준님 두 신호 → 입력
out = rec.recommend(needs, profile, type_nutrients=내_유형의_유형특이_영양소)  # 결과 = JSON으로 바로 보낼 수 있는 dict
```

**입력**
| 인자 | 형식 | 예 |
|---|---|---|
| `needs` | 영양소 → `High`/`Mid`/`Low` (재준님 `targets.json` 키 또는 한글) | `{'iron': 'High', 'calcium': 'Mid'}` |
| `profile` | 본인 정보 + 설문 안전 문항 | `{'sex': '여자', 'age': 35, 'smoker': False, 'pregnant_or_breastfeeding': False, 'kidney_disease_or_stones': False, 'anticoagulant_or_aspirin': False, 'current_supplements': ['vitamin_c']}` |
| `type_nutrients` (선택) | 내 유형의 유형특이 영양소 = **보조 판단 지표** | `['철', '비타민D']` |

**출력 (주요 키)**
`상태`(ok / 상담안내 / 추천영양소없음) · `안내`("이런 제품은 어떨까요?") · `상담안내`(공통 문구) · `추천영양소` · `식품으로만` · `장르`(충분함량형 / 편의형 / 가성비형(가격 후) / 종합형, 각 최대 3개) · 제품마다 `채우는영양소`, `함량미상`, `표시형태`, `주목적`, `지금드시는영양제와겹침`

## 2. 유형 기반(04)에서 바뀐 점
| 무엇을 | 유형 기반 (04) | 개인 (이 함수) |
|---|---|---|
| 필요 영양소 | 유형특이 1.0 / 공통주의 0.5 | 재준님 High 1.0 / Mid 0.5 / Low 제외 (같은 척도) |
| 성별·나이·흡연 필터 | 유형 평균 (남성비율·평균나이·흡연율) | **본인 값** → 더 정확 |
| 안전 문항 | 표시만 | **조용히 제외** (신장질환 → 칼슘·칼륨·인 함유, 항응고제 → 오메가3·비타민K 함유) |
| 임신·수유 | — | 추천 중단 + "전문가와 상담해 보세요" |
| 인·칼륨·나트륨 | 식품 안내 | 영양제 대신 `식품으로만`에 설명과 함께 |
| 보조 지표 | — | 유형특이 영양소가 개인 결과에도 있으면 +0.1, 개인 모델에 없는 비타민D·E만 0.3으로 추가 |

**그대로 쓰는 것**: 제품 주목적·목적일치(기능성 제품 오추천 방지), 종합형 분리, UL 초과 제외, 제조사·이름 중복 제거, 인기·브랜드 점수 안 씀

## 3. 표현 원칙 (11/3 회의, 의료법)
- 처방 뉘앙스 금지 → 안내 문구는 **"부족하기 쉬운 영양소를 채우는 데 이런 제품은 어떨까요?"**
- 질병별 "피해야 할 영양제" 안내 금지 → 안전 문항 해당 제품은 **화면 설명 없이 목록에서만 빠지고**, 모든 결과에 **"질환이 있거나 약을 드시고 계시면 전문가와 상담하세요."**

## 4. 검증 결과 (06 실행 값)
| 확인 | 결과 |
|---|---|
| 같은 입력이면 유형 기반 04와 같은 제품이 나오나 (11개 유형 × 3장르) | **33 / 33 일치** |
| 신장질환 응답 → 칼슘 채우는 추천 | 3칸 → **0칸** |
| 임신·수유 응답 | 추천 0칸 + 상담 안내 |
| 칼륨·인·나트륨만 High | 제품 없이 `식품으로만` 3개 |
| 현재 비타민C 복용 + 비타민C 제품 추천 | `지금드시는영양제와겹침: ['비타민 C']` 표시 |

## 5. 준혁님께 확인 부탁 🙏
1. **재준님 두 신호(Lifestyle / Habitual) 합치는 규칙**: 지금은 `needs_from_model`이 **둘 중 높은 구간**을 써요 (확률 평균은 안 함 — 재준님 원칙 유지). 다른 규칙이 좋으면 이 함수만 바꾸면 돼요
2. **현재 복용 영양제**: 설문이 성분만 받으면 지금처럼 '겹침 표시'만, 용량도 받으면 상한(UL) 합산 점검을 추가할 수 있어요
3. 필요한 파일: `제품분석/output/product_types.csv`, `product_features.csv`(01~03 실행 결과, 깃허브엔 없음) + 식약처 원본 CSV → 슬랙으로 드릴게요
