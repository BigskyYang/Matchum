# 개발자 적용 명세

## 1 설문

config/survey.ko.json의 선택 4문항 유지. 기존 v1.2.0 저장 응답을 그대로 사용함. 음식 섭취 문항 추가 없음. 질문을 건너뛰거나 모름을 선택했다고 활동 없음으로 변환하지 않음.

## 2 결과 카드 교체

기존의 별도 비타민 D 정보 영역은 제거하고, buildVitaminDCard/appendVitaminDCard로 생성한 결과를 기존 영양소 카드 배열에 연결함. 원격 웹의 카드 형식은 이 작업에서 접근하지 않았으므로 아래 명시적 계약을 웹의 실제 필드에 매핑함.

| 새 출력 | 기존 카드에서 표시할 위치 |
| --- | --- |
| nutrient_id / name | 영양소 ID / 이름 |
| source.label | 결과 출처 |
| reason.title | 살펴볼 이유 제목 |
| reason.text | 응답 조합을 해석한 설명 |
| reason.nextStep | 식품 안내로 이어지는 한 문장 |
| foodGuidance | 기존 식품 안내 영역 |
| productLink.categoryId | 기존 관련 제품 목록의 카테고리 |
| note | 결과 가까이에 짧게 표시하는 보조 안내 |
| activityNote | 관련 설명 또는 안내 펼침 영역 |
| productNotice | 제품 목록 안내 |

assessment.grade/probability는 null임. 이를 0, Low, 기본 등급으로 보정하거나 ‘부족’ 배지로 표시하지 않음. reason.patternKey는 내부 분기 키이며 위험 등급이 아님. 별도의 화면/카드 종류 디자인을 요구하지 않으며, 기존 카드가 등급을 필수로 요구하면 guidance의 경우 등급 슬롯을 비우고 출처를 표시하도록 수정함.

응답 근거가 되는 주요 3항목(점심/운동/휴일) 중 적어도 1개가 알려진 응답이면 카드를 추가함. 전부 미응답/모름이거나 출퇴근만 응답하면 개인화 근거가 없어 카드를 추가하지 않음. 출퇴근은 보조 맥락으로 evidence에 보존하며 노출량 판정에 사용하지 않음.

appendVitaminDCard는 기존 카드 순서를 유지하고 끝에 D를 추가함. 기존 D가 있으면 그 자리를 교체하고 중복을 제거함. 응답을 모두 지우면 추가된 D만 제거함. 다른 영양소의 내용/모델 결과는 변경하지 않음.

## 3 개수와 모델 선정

기존 예측 결과의 최대 5개와 선정 순서는 유지함. 생활문항 안내인 D는 모델 순위에 끼워 넣거나 기존 항목을 밀어내지 않고 동일 목록에 1개 추가함. 따라서 기존 카드가 5개이면 전체는 최대 6개가 될 수 있음. 화면의 고정 5개 자르기를 새 배열에 다시 적용하면 D가 사라지므로 기존 예측 선정 이후에 추가함. ‘부족 영양소 6개’처럼 전체 카드 수를 모델의 부족 판정 개수로 표시하지 않음. 이 개수 처리는 모델 성능 결론이 아니라 추가 카드 통합 정책임.

## 4 제품 목록·드롭다운

기존 productBridge v1.0.1은 vitamin_d를 selectedNutrientIds에 넣으면 거부하고, informationCategoryIds로만 요청하며 getNutrientDropdownOptions에서 제외함. 따라서 새 src/productAdapter.mjs를 함께 적용해야 함.

- selectedNutrientIds에는 기존 웹이 고른 모델 영양소만 전달함. D를 넣지 않음.
- buildProductsForResultCards가 D 카드 존재 시 informationCategoryIds에 vitamin_d를 명시적으로 추가함.
- 기존 카탈로그의 D 목록을 그대로 가져옴. connection_kind=information_only는 내부 출처 의미로 유지함. 이 값이 별도 화면을 강제하는 것은 아님.
- getResultDropdownOptions를 사용하면 같은 제품 드롭다운에 기존 영양소와 D를 함께 표시함.
- 기존 getNutrientDropdownOptions를 그대로 쓰면 D가 빠지므로 이 연결 지점은 교체해야 함.
- 다른 일반 정보인 종합비타민을 자동으로 드롭다운에 넣지 않음.
- 제품 목록·제형 필터·페이지당 20개·원본 정렬은 기존 함수를 재사용함. 새 점수·제조사 선별·추가 순위 없음.
- 기존 모델 응답이나 max 5 정책에 D를 학습 예측 결과로 기록하지 않음.

examples/webIntegration.mjs는 카탈로그와 기존 모델 선정 ID를 인자로 받는 실제 호출 예시임. 실제 웹은 기존 컴포넌트에서 제품 목록을 열던 방식 그대로 이 결과를 사용함. v1.2.0의 D 전용 식품/야외활동/제품 버튼 화면은 사용하지 않음.

## 5 인수 확인

1. 칼슘 등 기존 카드 옆에 D가 같은 레이아웃으로 보임.
2. 응답을 바꾸면 ‘살펴볼 이유’의 조합 해석이 달라짐.
3. D에 예측확률/High/Mid/Low가 생기지 않음.
4. D의 식품 안내와 제품 목록이 기존 흐름으로 열림.
5. 드롭다운에 D가 나타나고 제형/페이지 필터가 동작함.
6. 기존 예측 항목이 유지되고 D가 중복되지 않음.
7. 새 카드의 개수를 실제 결핍/부족 개수처럼 표시하지 않음.
8. 원격 웹 실제 UI 동작은 웹 담당자가 확인함.
